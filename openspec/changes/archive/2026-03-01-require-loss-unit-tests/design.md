## Context

既存 OpenSpec では Loss の命名や設定解決は定義されているが、Loss 単体での検証責務は明示されていない。このため、実装差分が統合テストまで遅延して発見される。今回の変更は、各 Loss ファイルが自己完結で最低限の挙動を検証できるようにし、回帰検知を早めることを目的とする。

## Goals / Non-Goals

**Goals:**

- `src/models/loss` 配下の各 Loss 実装に、`if __name__ == "__main__":` で走る簡易単体テストを必須化する。
- 簡易単体テストの必須チェック項目を仕様化する。
- 一時ファイル利用時の保存先と後始末（`multi-label/tmp`）を統一する。

**Non-Goals:**

- 既存 Loss アルゴリズムの数学的変更。
- GPU 前提の重い統合テストを Loss 自己テストへ持ち込むこと。
- 既存 pytest スイートを廃止すること。

## Decisions

1. Loss 自己テストの配置は各実装ファイル末尾に統一する。
   理由: 実装と検証の近接性を高め、変更時に同時更新しやすくする。
   代替案: tests 配下のみに集約。却下理由: 実装ファイル単体での即時検証ができない。

2. 自己テストの最小要件を 2 つに固定する。

- 正常系: 有限スカラーを返す。
- 異常系: 主要バリデーションの少なくとも 1 ケースで例外を確認する。
  理由: 過不足のない最小コストで回帰を検知できる。

3. NPMI 等の一時ファイルは `multi-label/tmp` のみ使用し、終了時削除を必須化する。
   理由: プロジェクト運用ルールと整合し、不要ファイルの残留を防ぐ。

4. 検証コマンドは `uv run python src/models/loss/<file>.py` を標準とする。
   理由: 実行環境の再現性を担保し、環境差異による誤検知を減らす。

## Risks / Trade-offs

- [Risk] 自己テストが増えることで実装ファイルが長くなる
  -> Mitigation: チェック内容を最小要件に限定し、冗長なケースは pytest 側へ分離する。

- [Risk] import 解決差で直接実行に失敗する可能性
  -> Mitigation: `uv run` 前提を明示し、必要な範囲で直接実行時の import 経路を考慮する。

- [Risk] 自己テストだけで仕様網羅したと誤認される
  -> Mitigation: 本要件を「最小安全網」と定義し、詳細検証は既存 pytest を併用する方針を明記する。
